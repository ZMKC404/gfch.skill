# 行动清单与避坑指南：结论必须落成"你该做什么"

> 11/12 有显式收束节；7/12 收束为编号建议清单，众数 3 条；4 篇把建议直接写进收束节标题。正例 = 原文短引 + 出处 id；反例均为 AI 腔构造句，非原文。

## 一、收束节的四种写法

1. **标准编号清单（首选）**：节名带承诺——"总结：给 AI 商业个体的三个锦囊"（chuhai-00004）、"总结：你的技术栈升级 SOP"（chuhai-00010）、"避坑指南：给 AI 个体商业者的三条建议"（chuhai-00000）。
2. **金句 + 规模句 + 引用收束**（进阶，语料唯一 chuhai-00006）：金句定调 → 由个案推及全体的规模句（"如果……那么……都将……"）→ 划线引用权威背书 → 末句压回一个当下动作："当你下次在 Cursor 中按下 Tab 键时，记得去给那些你赖以生存的工具点个赞助"（chuhai-00006）。
3. **加粗"结论："段**（chuhai-00000 例外型）：素材实在给不出可执行动作时，用一段判语收尾。
4. **清单 + 收尾金句**（chuhai-00002）："在独立开发的战场上，活下来并开启下一个项目，才是唯一的胜利。"（原文划线）

## 二、单条建议的写法（可照抄公式）

```
N. **动作短语（2-6 字）**：一句展开（做什么 + 为什么/怎么算赢）。
```

- 动作短语从素材原话提炼，展开不超过两句。
- 正例："**验证早于开发**：在写第一行代码前，先看有没有人愿意付那 $5。"（chuhai-00003）
- 正例："**验证先行**：在投入两年生命之前，先在 itch.io 发布一个原型。"（chuhai-00002）
- 反例（非原文）："建议：多做验证，多和用户沟通，保持初心。"——无动作短语、无判据，三条挤一行。
- 反例（非原文）："最后，希望这些建议对你有帮助！"——收束必须落在行动，不落在祝福。

## 三、清单纪律

1. **N 条就数得出 N 条**；众数 3，最多 4（chuhai-00003 为 4 条）。
2. **条与条不同轴**：一条管验证、一条管节奏、一条管杠杆（参照 chuhai-00003：验证早于开发 / 利用 AI 杠杆 / 利润再投资 / 雇佣 A 级人才）。同义反复 = 凑数。
3. 每条落到"今天能做"或"按什么判据做"的粒度。
4. 清单里的数字同样受防幻觉纪律管：素材没有的判据金额，写【待填：需回听核实】。

## 四、避坑指南体（负面清单的写法）

- **先分类，再判死刑**：自造命名式标签归堆，再每款一句话判死。正例骨架："##### 1. 增长陷阱类""##### 2. 僵尸技术类"（chuhai-00010）。
- 条目句式固定为"产品名：事实 + 缺失"。正例："**FreshBooks**：仅适合极简的发票开具，缺乏……工具"（chuhai-00010）；"**QuickBooks Desktop**：官方已放弃，继续坚守只会增加维护成本"（chuhai-00010）。
- **分类词带立场**："僵尸技术""旧时代残余"（chuhai-00010）——否定也要有立场，不做中性罗列。
- **节名自带数字承诺**："避坑指南：9 款不建议在 AI 时代投入精力的工具"（chuhai-00010）——数过再写。
- **正反配对**：避坑清单之后紧跟"进阶选择/核心推荐"（chuhai-00010 结构）；只有坏话没有替代 = 半篇横评。
- 反例（非原文）："当然，每款工具都有优缺点，大家可以根据自己的需求选择。"——和稀泥是拆解体大忌。
