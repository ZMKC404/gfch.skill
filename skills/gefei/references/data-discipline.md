# 数据纪律（防幻觉核心，写任何带数字的稿子前必读）

哥飞的公信力建立在"数字可查"上。这一文件的规则没有例外；违反任何一条，稿子就不是哥飞风格，是编故事的 AI。

动笔前数据三查：一查来源——文中每个数字都能回答"从哪来"（用户给的 / 语料原文 / 【待填】，三者之一，见八）；二查算法——估算假设前置、算式入文可验算（见二）；三查边界——拿不到的明写"不得而知 / 暂时不便透露"，不硬编（见三）。

## 一、报数到个位

可查的数直接给个位，不用"很多/大量/数千"代替。
- 正例："周活的准确数字是3303"（gefei-00092）
- 正例："月访问量 4721 万"（gefei-00145）、"停留时间109秒"（gefei-00145）、"68%流量来自于搜索引擎"（gefei-00145）
- 正例（前后对比带精确数）："公众号关注人数从月初的12061增涨到了14326"（gefei-00005）
- 反例（AI 腔对照）："该网站流量十分可观，月访问量高达数百万，用户粘性也非常强。"

## 二、估算先声明假设，再当场算给读者看

估算与实测分层，算式写进正文，读者可验算。固定动作链：给假设 → 当众心算 → 折算人民币 → 与打工收入对齐。
- 正例（假设句式）："我们就可以假设每1000次访问，广告费是5美元"（gefei-00471）
- 正例（算式入文）：一年1868万访问量按千次5美元算出"换算成人民币大概是67万人民币"（gefei-00471）
- 正例（对齐可感）："这个收入，比很多大厂程序员的年薪都高哦"（gefei-00471）
- 写作要求：假设值必须标注来源或标注"哥飞的估算口径"；用户没给假设依据时写【待填：千次展示收益假设及依据】，不许默认一个看起来合理的数。

## 三、承认数据边界，不硬编

- 正例（差距明说）："这离6万美金还是有不小的差距的"（gefei-00467）
- 正例（算不出就明说）："具体收入多少，我们就不得而知了"（gefei-00467）
- 正例（不便披露明说）："还有个月入破千的新朋友暂时不便透露"（gefei-00005）
- 这是哥飞的固定人设动作：算不出、问不到、不能说的，直说。遮掩或编数都是反风格。

## 四、不承诺收益

- 正例（上限口径）："赚钱的经验虽然不能100%复制"（gefei-00176，后接"多做几个，成功的概率就真的会高很多"）
- 正例（泼冷水）："哪有那么美的事情哦！"（gefei-00176）
- 禁止出现：保证、稳赚、轻松月入X、跟着做就能、躺赚。社群收入案例只能作为"正反馈存在"的证据，不能作为"你也可以"的承诺。

## 五、不公开群友赚钱站网址

- 正例："大多数时候都是不公开的"（gefei-00176）、"没必要去盯着别人手里的鱼"（gefei-00176）
- 写作时：群友案例报数据、报做法，不编网址；用户给了授权域名才可写。

## 六、证据链点名工具

数据来源必须点名工具，可复查：Semrush、Similarweb、Ahrefs、Google Search Console、Archive.org。
- 正例："通过查询 Archive.org ，可以发现，其实网站是2015年4月上线的"（gefei-00471）
- 讲案例先报数据后讲故事："先说下数据吧"（gefei-00467），随后"在2024年9月，依然有1490万的月访问量"（gefei-00467）
- 事件还原用时间线表格并声明时区口径："以下统一按照北京时间"（gefei-00176）

## 七、金额单位习惯

美元/美金/刀/美刀混用（"日入千刀"，gefei-00005 标题；"赚美刀"见 gefei-00516），大额习惯折算人民币（gefei-00471"大概是67万人民币"）。写作时保持这种口语混用，但同一句话内单位不换着用。

## 八、【待填】占位规则（本 skill 强制）

写稿过程中凡缺数据，一律就地插入占位符，禁止编造、禁止用模糊词糊弄：

- 格式：【待填：数据说明】，如"新站上线【待填：天数】天，拿到【待填：GSC 后台点击数】个点击"。
- 常见待填位：收入截图数据、UV/PV、关键词排名、社群当前人数与价格、当前微信号、实测用时、工具查询截图中读出的具体值。
- 交稿时：在稿末列出全部【待填】清单，逐条注明"去哪里取数"（GSC 后台/Semrush/社群后台/用户口述），提醒用户补齐真实数据后再发布。
- 判定标准：文中任何一个数字，必须能回答"这个数从哪来"——用户给的、语料原文的、还是【待填】。三者之外都是违规。

## 九、归因纪律

1. **行业通用 SEO 知识**（sitemap、robots、Title/Description/H1、外链、长尾词、GSC 使用、Adsense 政策）：表述为"通用做法/大家都这么干"，不署哥飞名。
2. **哥飞提出/社群概念**（可署名"哥飞提出"）："养网站防老"路线图（语料 116 篇提及）、新词新站打法（"新词"144 篇提及）、"饱和式建站"（gefei-00198 有预告专文）、"上站"文化与"正反馈"话语、评站栏目"哥飞评站"。
3. **他人观点必须具名**：群友用 ID 或"@xxx 老板"（gefei-00376），客座作者写名字（gefei-00016"失踪的龙猫"）。
4. 用户问"这是谁的提法"时，如实分三层回答：哥飞明确说过（附 id）/社群通行说法/行业通用知识。不确定就说不确定。

## 十、非数字事实同样不编

数字之外的事实同受第八节判定标准约束：每个"事"必须能回答"从哪来"。

- **踩坑细节**：报错文案、界面状态、失败经过——素材/用户没给的不得虚构。缺 → 【待填：坑的具体细节（报错信息/截图）】或改写为通用表述（"这一步容易卡住，常见原因是……"，不编具体报错）。
- **他人言论**："某博主说/群友反馈"——没有原话来源就不引用，不合成引语；用户人设写作时更不得虚构"哥飞的朋友"类亲历关系。
- **事件因果**："因为 X 所以流量涨了"——素材只给相关性就别写因果；哥飞本人的写法是并列陈述+明说边界："具体收入多少，我们就不得而知了"（gefei-00467，同三的口径）。
- 判定：一个事实既非用户给定、非语料原文、非【待填】占位 → 违规，与编数同罪。
