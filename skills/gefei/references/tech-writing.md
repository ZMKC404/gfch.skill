# 技术写作：教程四件套、评站报告体、图文配合

哥飞的教程写法 = 把一次真实操作全程录音转文字，再补上"为什么"和"坑"。正例均为语料原文短引（id 已核验），反例为 AI 腔对照（非原文）。

## 归因声明（先读）

Sitemap、robots.txt、Title/Description/H1、外链、长尾关键词、GSC、Adsense 政策等是**行业通用 SEO 知识**，哥飞是讲解者不是发明者，写作时不得表述为"哥飞提出/哥飞独创"。哥飞提出的独特打法——"养网站防老"路线图、"新词新站"选品法、"饱和式建站"、评站栏目"哥飞评站"——可署名"哥飞提出/哥飞的栏目"。

## 教程四件套

**1. 步骤拆到按钮和字段级。**动词开头，界面元素用原文英文加引号，路径精确到"左侧菜单栏→右侧按钮"。
- 正例："打开 https://www.cloudflare.com/ ，注册登录"（gefei-00197）
- 正例："点击右侧的“Add a site”按钮"（gefei-00197）
- 正例（二级编号）："1.1、Title"（gefei-00376）
- 反例（AI 腔对照）："首先，我们需要在 Cloudflare 平台上完成域名的相关配置。"

**2. 每步当场讲为什么。**步骤做完必补一句目的，让读者能迁移。
- 正例："放在 body 最后，是为了不让统计代码拖慢网站加载"（gefei-00198）
- 反例（AI 腔对照）："将统计代码放置在合适的位置即可，这里不再赘述。"

**3. 安抚 + 降级方案。**每处"要等待"的环节明说等待，每处环境差异给退路。
- 正例（等待型安抚）："刚添加好的dns解析服务不会那么快生效"（gefei-00197），紧接"等待就行"（gefei-00197）
- 正例（降级方案）："如果你的电脑没有谷歌浏览器也没关系，有什么浏览器就用什么"（gefei-00190）
- 正例（完成哲学）："有比没有好，完成比完美更重要，请尽快上线第一版"（gefei-00197）
- 反例（AI 腔对照）："DNS 生效需要一定时间，请耐心等待，具体时长视情况而定。"

**4. 主动报坑。**写到会出错的步骤，先报自己踩过的坑和后果。
- 正例："如果你用全新注册的 Github 账号去注册 Vercel"（gefei-00197，紧接提醒很可能刚注册就被封号）
- 正例（边做边认错）："刚才哥飞不小心在仓库名字后面多了一个空额"（gefei-00296），随后"赶紧去修改了仓库名称"（gefei-00296）
- 反例（AI 腔对照）："操作过程中如遇问题，请自行查阅官方文档。"

## 先做后教的记时写法

- 教程给时间量化承诺："如果只是做网站，半小时内肯定能够搞定"（gefei-00296）
- 配实测计时当证据："域名是11:38注册的，现在是12:40"（gefei-00296）
- 写作要求：给"多久能做完"的预期时，必须来自真实计时或用户给的实测数据；没有就用【待填：实测用时】占位。

## SEO 术语解释（行业通用知识）

- 大白话定义先行："所谓 Sitelinks ，其实就是谷歌挑选的该网站比较重要的一些内链"（gefei-00258）
- 判定给结论不留悬："哥飞不推荐大家用 Keywords，所以这里不写是对的"（gefei-00376）
- 建议具体到字符串，不停留在"要重视 H1"："哥飞建议一个页面只放一个H1，在H1里放你网站要做的核心关键词"（gefei-00376）

## 评站报告体（"哥飞评站"是哥飞的栏目）

固定骨架（gefei-00376 全篇可作参照）：
1. 开场"大家好，我是哥飞" + 一句话介绍被评的站
2. 页面结构盘点 → 逐页按 Title/Description/H 标签/图片/链接/社媒过一遍
3. 每节小结，最后给"建议新增页面"清单
4. 标题明码标价字数（"……SEO评测报告和改进建议4000字"，gefei-00376）

单条句式：**先陈述看到的问题 → 给建议 → 落到该站具体该写什么。**
- 正例："再看 Headings ，会发现这个网站的 H 标签使用混乱"（gefei-00376），随后"首页用到了两个 H1"（gefei-00376），建议落到"如这个网站可以体现“Sticker Maker”这个关键词"（gefei-00376）
- 批评用语克制："使用混乱"就是最重的词；不用"灾难/垃圾/离谱"
- 反例（AI 腔对照）："该网站的 H1 使用存在一定问题，建议进一步优化提升。"

## 图文配合（有图有真相）

- 图是证据，不是装饰：数据截图必配数字文字："先上图，有图有真相"（gefei-00434），"Adsense广告收入874美元"（gefei-00434）
- 每张图前有一句文字指认："哥飞这个注册商的界面长下面这样。"（gefei-00197）；"请看下图"（gefei-00309）
- 交代图的口径，防读者误读："刚才为了给写文章配图没有广告，哥飞特意把广告关闭了"（gefei-00471）
- 写作规则：每张图位写一行"下图/上图/截图"指认语 + 图要证明的一句话；无图的稿子（用户未提供截图时）在图位留【待填：截图说明——需展示什么数据】，不凭空描述截图内容
- 反例（AI 腔对照）："从下图可以清晰地看出，该网站的各项指标表现十分优异。"（图里是什么数据都没说）

## 教程反模式

- 步骤跳级："配置好服务器"一句话带过 SSH、面板、部署全过程
- 只命令不解释：全程"点击A→点击B"，无一处"为什么"
- 假装顺利：不报坑、不提等待，读者一遇到报错就弃
- 编造界面细节：没操作过就写"在右上角找到XXX按钮"——没把握就【待填】并请用户核对
